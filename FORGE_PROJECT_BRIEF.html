Black Box: CI on your home PC

Use Cloudflare Workers Free to choose where CI runs. Your WSL2 runner does the work and sends results directly to GitHub. The home path uses no GitHub-hosted minutes.

What “free” includes

Workers Free allows 100,000 requests per account per day and 10 ms CPU per invocation. Network waiting is not CPU time. Stay on the Free plan and test usage. Limit errors must stop or defer routing, not enable paid services. [2]

A tiny D1 Free table can retain pending requests and reject duplicates. Its separate limits also need monitoring. It will not hold build logs, artifacts, or caches. [3]

Private GitHub-hosted jobs use included minutes. Blacksmith is a separate paid fallback. GitHub artifact and cache storage can still incur charges beyond allowances. These are separate from free routing and home compute. [1]

How your computer receives the job

Worker chooses. GitHub coordinates. WSL2 executes.

  1. 1. You push to GitHubGitHub sends the App a webhook with repository, commit, and pull-request metadata.
  2. 2. Cloudflare WorkerVerify the event and trusted repo. Check availability and cost policy. Choose home, an enabled fallback, or waiting.
  3. 3. Back to GitHubWorker calls GitHub’s API to start the workflow with the selected runner and intended commit. No hosted routing job.
  4. 4. Windows + WSL2The official runner collects its job from GitHub. It runs AMR’s commands and reuses local package and Docker caches.
  5. 5. Results in GitHubThe runner uploads logs and results directly. The App associates the result with the original pull-request commit.

The PC connects outward over HTTPS. No home port forwarding or tunnel is needed. Worker handles routing metadata, not source downloads, Docker layers, or CI logs. [4]

Windows, WSL2, and the runner must be running. Docker must be available for database and container tests. Begin with one concurrent job for the shared 16 GB RAM budget.

If no allowed fallback is available, keep the request waiting and retry. GitHub-hosted fallback needs permission to consume private-repo minutes; Blacksmith needs installation and its own budget. Worker cannot wake a powered-off PC or move an already-running job to another provider.

AI can later explain selected failure logs or propose a fix for a separate small fee. CI runs without AI. Proposed patches need tests and your normal review.

No fallback spend is enabled by this plan. Automatic routing does not make fallback compute free.

What changes in your workflow

Workflows stay in .github/workflows/. A dispatch input chooses the runner before GitHub queues the job. This automatic version needs more configuration than changing one runs-on line. [5]

Illustration only, not an installable workflowYAML
on:
  workflow_dispatch:
    inputs:
      runner:
        type: choice
        options: [black-box-linux]
        default: black-box-linux
        required: true
      commit:
        type: string
        required: true

jobs:
  local-checks:
    runs-on: ${{ inputs.runner }}
    # Checkout the validated commit.
    # Preserve the existing AMR steps.

black-box-linux is a proposed label. Only configured providers may enter the allowlist. Preserve AMR’s commands, pinned Actions, timeouts, security schedule, and cancellation behavior.

PR integration needs a real test: a dispatched run has a different event context. Test the intended revision, preserve merge-check behavior, and attach the result to the right PR commit. Replace original triggers carefully to avoid duplicate hosted runs.

Setup decisions in plain English

Windows, Firecracker, KVM, and image drift

The runner is GitHub’s program that executes jobs. The dispatcher is the Worker that chooses the runner. WSL2 supplies Linux while Windows stays installed. Docker supports WSL2 integration; check the existing setup before installing another engine. [6]

Image drift means GitHub and your PC have different tool versions. A documented version checklist and real workflow tests are enough to start.

KVM runs virtual machines on Linux. Firecracker uses it to create small VMs. Neither is needed for v0.1. [7]

What happens to the caches when the PC is off?

Files on disk remain after a normal shutdown. RAM does not. Downloads happen on a cache miss; caches do not need constant writing while idle. Keep the workspace and package cache in WSL’s Linux filesystem.

Start with local pnpm and Docker builder state. GitHub’s actions/cache still uses GitHub storage by default on self-hosted runners. Replacing that service is separate work. [8]

Trusted code and private repositories

Allow only repositories and executable code you trust. School-repo setup still needs its owner’s authorization. AMR admin access has been observed, but no App is installed.

Local storage does not automatically protect personal files. Use CI-owned workspaces and database volumes. A persistent WSL runner is not a fresh isolated machine per job.

Cloudflare processes private repository metadata and holds App credentials securely. Verify webhook signatures and expose no public job history. Builds and logs do not pass through Worker.
