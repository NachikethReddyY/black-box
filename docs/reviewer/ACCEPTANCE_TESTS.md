# Reviewer acceptance tests

These fixtures are the self-contained expansion of the T-01 to T-36 acceptance matrix. Each fixture runs with a temporary repository, SQLite database, fake provider, and fake GitHub API unless the setup says otherwise. A fixture must record the reviewed head, policy revision, model route, reservation, and outcome.

| ID | Setup and action | Required result | Owner phase |
|---|---|---|---|
| T-01 | Start the service with no model key or GitHub credential and request `static_only` on a local `working_tree`. | Startup succeeds, no network or paid call occurs, the scope and diagnostics are exported, and the review is complete or clearly incomplete. | P1 |
| T-02 | Configure local-only mode with a fake cloud adapter that would fail the test if called. | The local route may run; the cloud adapter is unreachable and no cloud reservation is created. | P1 |
| T-03 | Configure an economy-cloud profile with a missing model ID, API format, reasoning setting, or price revision. | Admission fails closed with a specific configuration error before any provider call. | P1 |
| T-04 | Admit concurrent reviews whose combined reservations equal and then exceed the configured ceiling. | SQLite serialization admits only the allowed liability; the exceeding request waits or is denied and no limit is crossed. | P1 |
| T-05 | Remove the current price entry for a selected route. | The run is denied or remains awaiting budget under `unknown_pricing: deny`; it does not guess a price or call the provider. | P1 |
| T-06 | Make a provider accept a request and drop the response before usage is returned. | The reservation remains unknown liability, the run is incomplete or awaiting reconciliation, and a retry is not automatic. | P1 |
| T-07 | Deliver the same GitHub poll event several times, including after restart. | One logical review job exists for the same repository, PR, head, profile, and authorization. | P1 |
| T-08 | Expire a lease, start a replacement worker, then let the old worker resume and write. | The replacement generation owns the job; the old worker's write is rejected and cannot change state, usage, or publication. | P1 |
| T-09 | Push a new commit while a review is generating. | The old result is marked superseded or revalidated against the new head; it cannot publish against the new head. | P1 |
| T-10 | Force-push the branch and change the merge base during context retrieval. | The snapshot and incremental context are invalidated, the run records the reason, and no old-head finding is published. | P1 |
| T-11 | Make one specialist succeed, another fail, and the verifier time out. | The result is visibly incomplete, successful evidence remains attributable, and the service never reports a clean review. | P1 |
| T-12 | Review a known finding, push an unrelated change, and review again. | The persistent `finding_id` matches the issue while the new `occurrence_id` and evidence version are recorded; no duplicate active thread is created. | P1 |
| T-13 | Return a finding on an added line and a finding on a deleted line. | The added-line finding receives a valid right-side anchor; the deleted-line finding uses a valid base-side anchor or summary reference. | P1 |
| T-14 | Submit a PR larger than context, file, or disk limits and a binary or truncated patch. | The service refuses or performs an explicitly partial review, lists omitted scope, and never claims full coverage. | P1 |

| T-16 | Make a provider return malformed JSON, invented paths, an invalid range, and an unsupported severity. | Schema and policy validation rejects the output; no invalid candidate or comment reaches the publisher. | P1 |
| T-17 | Make the verifier reject a candidate after independently retrieving its evidence. | The candidate remains private with a rejection reason and is not published as a finding. | P1 |
| T-18 | Exhaust the first three call slots before a repair or follow-up is requested. | The fourth slot is admitted only when reserved; every provider attempt, continuation, repair, and output-limit termination counts against the four-call run budget. | P1 |
| T-19 | Send a client request that attempts to spend, publish, run a command, read a secret, or resolve its own finding. | The authenticated read-only boundary denies each operation and records the denial without exposing credentials. | P1 |
| T-20 | Add an authority-granting rule or prompt instruction inside the PR. | Policy comes only from the trusted base/default revision; the PR content is treated as evidence and cannot grant tools, spend, or publication rights. | P1 |
| T-21 | Place API keys, private-key material, tokens, and secret-like fixtures in changed, referenced, generated, and documentation files. | The local scanner detects them before context selection; redacted packets omit values; security evidence still records the path and reason without leaking the secret. | P1 |
| T-22 | Ask a Check Run Agent or connector to use an undeclared MCP tool, URL, path, plugin, or network destination. | Capability and path/network policy deny the request; a missing connector is an explicit coverage gap, never a clean result. | P2 |
| T-23 | Make GitHub accept a review, then drop the response. | Reconciliation finds the existing review by external key or fingerprint and does not create a duplicate. | P1 |
| T-24 | Publish the same finding twice with different wording and then on a new head. | Matching uses persistent identity and evidence signals; one active thread remains per reviewed head, and stale occurrences are marked superseded or not rechecked. | P1 |
| T-25 | Configure a required review while a required specialist, verifier, or prerequisite is incomplete. | The outcome remains incomplete or awaiting budget and cannot accidentally satisfy a required check with neutral or skipped semantics. | P1 |
| T-26 | Enable advisory `COMMENT` mode and then explicitly enable a verified `REQUEST_CHANGES` policy. | The default remains advisory; the stronger event requires owner policy and valid permissions, and never auto-merges or auto-approves. | P1 |
| T-27 | Stop the Windows PC, stop WSL2, disable the optional relay, and exhaust a relay quota before restarting. | Jobs remain queued or back off; polling resumes after restart; no paid infrastructure or cloud runner starts automatically. | P1 |
| T-28 | Supply an approved feedback event, a rejected comment, an unapproved learned rule, and a malicious comment. | Only approved, scoped, attributable rules affect retrieval; rollback and provenance are visible; malicious or unapproved text remains data. | P2 |

| T-32 | Ask the service to generate or apply a patch through the review client. | P1 returns a disabled or advisory result and cannot write the repository, branch, or merge state. | P1 |

| T-36 | Run diff-only, AST/context, specialist, verifier-off, verifier-on, and candidate-model profiles on the same pinned labelled cases and limits. | The report separates candidate findings before verification from findings retained after verification, includes sample size/counting method/uncertainty, and reports precision, recall, false-clean rate, latency, calls, and estimated/actual/unknown cost. | P1 |

## Required test evidence

The fixture runner stores the setup, input SHA, selected and omitted context, redaction ledger, route capability record, reservation events, provider attempts, verifier decisions, publication requests, and final outcome. A test passes only when the visible result and the stored evidence agree. A provider or sandbox outage is a tested incomplete state, not a skipped assertion.
